# GENE ORDER 基本戦闘

## HP自然回復

生存中の場のキャラクターは、毎ターン終了時に `character.csv` の `regen_value` 分を回復する。最大HPで上限を処理し、0・満タン・戦闘不能・控えには回復イベントを発生させない。通常交代したターンは交代先が対象になる。戦闘不能後の補充は終了処理の後に行うため、その補充個体は登場ターンの自然回復対象にならない。

移植元 `C:/Users/b16e1/Documents/MHB/MHB/app.js` の `endRound()` は、継続ダメージ・戦闘不能判定、終了時能力パッシブ、自然回復、EN回復の順。GOは既存の双方同時継続ダメージ・勝敗判定を保ち、継続ダメージ・戦闘不能・勝敗・期限処理 → 場の生存個体のターン終了パッシブ → HP自然回復 → EN回復 → 補充の順で処理する。勝敗確定後は自然回復を行わない。補充選択からの再開でも同じターンの回復を繰り返さない。

実回復量が正の時だけ `heal` イベントに `source: natural` を付けて記録し、自然回復のテキスト・HPゲージ・回復演出に反映する。回復量は共通の `naturalRecovery()` を使う。`previewTurnEndRecovery()` は現在の状態異常と締め付けによるダメージを差し引いてから自然回復を予測する読み取り専用関数。HP0に達した個体を復活させない。

通常の `previewDamage()` は従来どおり技単体の直後を予測する。ターン末のHPは別の予測として扱う。自然回復により被ダメージを相殺する対面が生じることは仕様どおり。検証用のターン上限を正式な引き分け条件には使用しない。既存のCSV数値は維持する。

## ダメージ

物理技はPA / PD、特殊技はSA / SDを使用する。実戦と将来の予測表示・AIは `geneOrderBattle.calculateDamage()` を共有する。この関数はHP、EN、能力ランク、パッシブのフラグを更新せず、乱数や急所判定を行わない。

1. 技威力と、能力ランク適用後の攻撃・防御能力を決める。
2. 基本値を `floor(22 × power × attack / (50 × defense)) + 2` で求める。
3. 攻撃属性が使用者のどちらかの属性に一致すれば、STAB 1.25倍を一度だけ適用する。最も近い整数に丸め、0.5は切り捨てる。
4. `element_effectiveness.csv` から各攻撃属性について防御側属性の相性を乗算する。攻撃属性が2つなら、その結果の0倍を除いて乗算する（全部0なら0）。合成倍率を掛けて切り捨てる。
5. 最終補正を掛け、STABと同じ規則で丸める。通常の有効な攻撃は最低1。属性無効や完全防御を表す入力は0。
6. ターン処理で残りHPを上限としてダメージを適用し、HP 0で戦闘不能とする。

単属性・2属性の攻撃技を対象とする。無属性 `none` もSTAB・相性表を使う。空欄の第2属性は相性に参加しない。変化技はダメージを発生させず、通常効果と戦闘効果を処理する。

`hit_type=guard_break` は個体・場の該当する軽減率を半分だけ残す。たとえば 50% 軽減は 25% 軽減となり、複数の軽減はそれぞれこの規則で乗算する。属性無効、回避、反射・吸収の優先順は変えない。第2属性を持つ攻撃技は、相性・STAB・無効化の正式な合成規則が未確定のため選択不可とする。

威力80、PA120、PD100では基本44。STAB後は等倍55、弱点110、耐性27、無効0。PA＋1ならPA180、基本65、STAB・等倍で81。

## 能力・EN

HP以外の5能力に独立した戦闘ランクを持つ。初期値0、範囲−6～＋6。能力値は基礎値に有理数の倍率を掛け、切り捨てて最低1にする。ランクが0以上なら分子・分母は `(2 + stage)/2`、負なら `2/(2 - stage)`。通常交代で退く個体のランクをリセットする。図鑑ランクやMHBの百分率補正とは別の状態。

初期EN 1、最大EN 7は暫定。技が成立した時にCSVの `cost` を支払い、無効化された攻撃も消費する。選択時の不足や、行動前に倒れた場合は消費しない。

## ターンと暫定ルール

- 両側の行動を検証し、パッシブ補正後の優先度、補正後SP、同値時の乱数の順で並べる。テストでは乱数関数を注入できる。通常交代の優先度は暫定＋6。
- 交代後に攻撃する側は、その時点で場にいる相手を対象とする。先に倒れた個体の予約行動は実行しない。
- 控えが全員倒れている側は敗北。控えが残る場合は、ターン終了時に編成順の次の生存個体が自動で出る。正式な交代先選択と交代時効果は今後設計する。
- 暫定的に生存して場にいる個体へターン終了時に `cost_charge` 相当のENを加算する。通常交代で出た個体も対象。待機に特別なチャージ効果はなく、控えと戦闘不能による補充直後の個体はそのターンの回復対象外。保持ENは通常交代で変わらない。勝敗確定したターンには回復処理を行わない。
- 確認画面は固定編成の両側を手動操作する。CSVの `slot`、正式な編成上限、敵AI、自然HP回復、特殊な引き継ぎは仕様確認待ち。

## v0.30の技・効果

- 行動順を確定したあと、技が成立した時点でENを消費する。ダメージを計算・適用し、通常効果1～3、戦闘効果1～2、戦闘不能・勝敗イベントの順で処理する。HPが0になった時点で戦闘不能フラグを立て、行動順はランクが変わっても再計算しない。
- 通常効果は自分・相手の指定を使い、発生率0%では発生せず100%では確定。中間は注入可能な乱数で判定する。符号付き段階値は changeStage に直接渡し、通常交代時まで持続する。最大HP回復・実ダメージ吸収はいずれも切り捨て、回復後のHP・ENに上限を適用する。
- 共通回避は4枠の外にあるEN0・優先度+4の行動。刃研ぎと同じ処理で、CSVの回避率を0～100%に制限し、行動成立時に判定する。空欄は暫定0%。成功状態の取得と、攻撃を回避したことは別のイベント。回避不可は回避状態だけを無視する。属性無効も成立する場合は回避イベントを出さない。
- 半減防御はマスタの bf_half_guard に基づき、最終倍率0.5を共通計算に渡す。回避と半減は独立した状態で、いずれもターン終了時に解除。連続回避ペナルティは今回導入しない。
- 回避・属性無効では敵への追加効果を適用せず、実ダメージ0では吸収しない。自己能力低下は技を実行した時点で成立。変化技は回避や攻撃相性で無効化されない。戦闘不能になった相手へ追加効果は適用しない。
- シェルハードは `skill.csv` の `attack_stat=phy_def` により攻撃側PDを参照し、攻撃後に自分のPDを1段階下げる。`attack_stat` が空欄なら技分類の通常値（物理攻撃か特殊攻撃）を使う。窮鼠猫噛は攻撃実行時のHPが1の場合だけ、正式ルール表と威力上限から160を得る。HP2以上では70。

## 拡張と未対応機能

v0.20の行動経路は旧MHBの相性平均、ダメージ乱数、能力百分率、効果発動処理を呼ばない。既存のMHBコードは参照用として保持する。GOの予測と実戦は共通計算を使い、将来的に技・パッシブで確定した威力、攻撃参照能力、最終倍率、完全防御を入力として渡せる。確定急所の仕様は未定義。技・パッシブのランク変化は `changeStage()` へ接続する。

未対応の効果を一つでも含む技は理由を表示して選択不可とする。火やられ・反射・身代わり・特殊交代・パッシブは今後対応。[技の一覧](skill-effects.md) と [データ診断](data-foundation.md) を参照。

## 複合属性技

第2属性が空欄・noneなら単属性、同じ属性は重複排除する。STABは使用者のどちらかの属性と一致すれば既存1.25倍を一度だけ適用する。属性相性の0倍除外は攻撃属性の合成にのみ適用し、防御側の複合属性の乗算中には適用しない。属性無効パッシブは別判定であり、一方に一致すれば技全体を無効にする。計算順、相性表、能力値、威力は変更しない。検証結果と相互作用は[複合属性技](dual-elements.md)を参照。

## 優先度補正の確定と消費

行動順決定時にpriorityDetailsを取得してその行動の優先度を固定し、実行時の途中HP変動で再計算しない。previewDamageとAIはeffectivePriority／priorityDetailsを共有し、予測では発動回数や履歴を変えない。技が使用成立した時にだけ補正の発動ログ・回数と登場後使用履歴を更新する。睡眠・麻痺・EN不足・戦闘不能・回復封印・技不成立・交代待ちの不正入力は消費しない。溜め開始は使用成立、解放は別ターンの優先度としてその時点で判定する。無鉄砲のHP費用も当該行動の確定済み優先度を参照する。
