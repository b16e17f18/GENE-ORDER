# GENE ORDER v0.20 基本戦闘

## ダメージ

物理技はPA / PD、特殊技はSA / SDを使用する。実戦と将来の予測表示・AIは `geneOrderBattle.calculateDamage()` を共有する。この関数はHP、EN、能力ランク、パッシブのフラグを更新せず、乱数や急所判定を行わない。

1. 技威力と、能力ランク適用後の攻撃・防御能力を決める。
2. 基本値を `floor(22 × power × attack / (50 × defense)) + 2` で求める。
3. 攻撃属性が使用者のどちらかの属性に一致すれば、STAB 1.5倍を一度だけ適用する。最も近い整数に丸め、0.5は切り捨てる。
4. `element_effectiveness.csv` の倍率を掛けて切り捨てる。防御側が複合属性なら各倍率を乗算する。
5. 最終補正を掛け、STABと同じ規則で丸める。通常の有効な攻撃は最低1。属性無効や完全防御を表す入力は0。
6. ターン処理で残りHPを上限としてダメージを適用し、HP 0で戦闘不能とする。

単一属性の攻撃技を対象とする。無属性 `none` もSTAB・相性表を使う。空欄の第2属性は相性に参加しない。変化技は攻撃計算の対象外。

威力80、PA120、PD100では基本44。STAB後は等倍66、弱点132、耐性33、無効0。PA＋1ならPA180、基本65、STAB・等倍で97。

## 能力・EN

HP以外の5能力に独立した戦闘ランクを持つ。初期値0、範囲−6～＋6。能力値は基礎値に有理数の倍率を掛け、切り捨てて最低1にする。ランクが0以上なら分子・分母は `(2 + stage)/2`、負なら `2/(2 - stage)`。通常交代で退く個体のランクをリセットする。図鑑ランクやMHBの百分率補正とは別の状態。

初期EN 1、最大EN 7は暫定。技が成立した時にCSVの `cost` を支払い、無効化された攻撃も消費する。選択時の不足や、行動前に倒れた場合は消費しない。

## ターンと暫定ルール

- 両側の行動を検証し、優先度、補正後SP、同値時の乱数の順で並べる。テストでは乱数関数を注入できる。通常交代の優先度は暫定＋6。
- 交代後に攻撃する側は、その時点で場にいる相手を対象とする。先に倒れた個体の予約行動は実行しない。
- 控えが全員倒れている側は敗北。控えが残る場合は、ターン終了時に編成順の次の生存個体が自動で出る。正式な交代先選択と交代時効果は今後設計する。
- 暫定的に生存して場にいる個体へターン終了時に `cost_charge` 相当のENを加算する。通常交代で出た個体も対象。待機に特別なチャージ効果はなく、控えと戦闘不能による補充直後の個体はそのターンの回復対象外。保持ENは通常交代で変わらない。勝敗確定したターンには回復処理を行わない。
- 確認画面は固定編成の両側を手動操作する。CSVの `slot`、正式な編成上限、敵AI、自然HP回復、特殊な引き継ぎは仕様確認待ち。

## 拡張と未対応機能

v0.20の行動経路は旧MHBの相性平均、ダメージ乱数、能力百分率、効果発動処理を呼ばない。既存のMHBコードは参照用として保持する。GOの予測と実戦は共通計算を使い、将来的に技・パッシブで確定した威力、攻撃参照能力、最終倍率、完全防御を入力として渡せる。確定急所の仕様は未定義。技・パッシブのランク変化は `changeStage()` へ接続する。

未実装の威力ルール、効果、特殊命中種別、変化技は理由を表示して選択不可とする。回避・毒・火傷・吸収・反射・身代わり・壁・特殊交代・パッシブの発動は今後対応。v0.10からの未解決参照70箇所は [データ基盤の記録](data-foundation.md) を参照。

## 検証

既存のデータテスト12件と新規の戦闘テスト13件を `node --test` で実行する。正式CSVによる統合戦では、ミズアメネバムシとメトロシーザがウォーターショットを使用し、毎ターン18対19ダメージ。9ターン目にミズアメネバムシが残りHP4で勝利する。
