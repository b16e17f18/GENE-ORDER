# v0.60 MHB画面の接続

| 画面 | MHBから利用 | GO側の接続 |
|---|---|---|
| タイトル | `#titleView`、`.title-stage`、既存ボタンとパネル | ゲーム名・版・対戦・図鑑・デバッグを文字で表示 |
| 編成・詳細 | `#setupView`、左右のチーム枠・キャラクターカード・詳細、`detailStat()` | 正式CSV、先発選択、習得技・パッシブ・参加不可理由 |
| 戦闘・行動・交代・勝敗 | `#battleView`、HUD・ゲージ・背景・グリッド・状態パネル、`renderSprite()`、`renderEnergySegments()` | GOの戦闘状態・ランク・7属性、正式な入力と交代再開、勝敗・再戦 |
| 図鑑 | `#dexOverlay`、一覧・プロフィール・能力グラフ | 名称設定済み46体。技・画像・パッシブの未設定を表示 |
| 音響とモーション | `playBgm()` / `stopBgm()`、既存モーションレイヤーとフレーム計算 | 対戦開始操作でBGMを再生。`animation.csv` で定義した技演出を対象側に表示。素材のないイベントはゲージとメッセージ、明滅で表示 |

`initializeGeneOrder()` は正式10 CSVを読み込み、固定編成デバッグと正式画面の両方を準備する。 `go-ui.js` がMHBテンプレートから必要な画面だけを挿入する。 `styles.css` はMHB由来の元データ。少量の `go-ui.css` でGO画像の寸法、4属性の補助色、狭い画面と数値の表示を調整する。正式なゲーム進行、ショップ、所持・育成、交換・持ち物、セーブ、チュートリアルは未接続。

正式な編成上限は仕様確認待ち。対戦確認用の暫定設定は各側1～4体、同一チーム内で同じキャラクターは1体まで。両側で同じキャラクターを選ぶことはできる。CSVのスロットは詳細に表示し、合計による制限は設定しない。先発を並べ替えて `createBattle()` に渡す。属性・基礎能力と少なくとも1件の使用可能な習得技があるキャラクターを編成できる。

GO戦闘状態は `geneOrderBattle` が管理する。 `createMatch()` は `checkAction()` と `resolveTurn()` / `continueSwitch()` に行動を渡し、イベントを公開履歴に記録する。AIは `geneOrderAI.observe()` が切り出した情報で判断する。手動対手動では両側の行動を選び終えてからターンを解決する。AI対AIは1操作で1ターン進む。デバッグのAI採点はデバッグ画面で確認できる。

イベントごとに記録した描画用のフレームを順に使い、ターンまたは交代選択待ちの状態で最終状態に同期する。入力は行動選択・解決・AI処理・演出・交代選択・勝敗に分かれる。対戦を離れるか再戦すると以前の演出を破棄する。スキップとOSのモーション軽減設定に対応する。

初回の接続で使用した素材は `asset/battle-animation/` の5画像、`asset/bgm/free-battle.mp3` と既存GO画像。BGMはMHBの `battle_f_1.mp3`、アニメーションはMHBの対応する画像の複製。GO専用タイトル絵、キャラクター064の画像、独立した効果音が不足している。画像未設定は代替表示。再生が制限された場合も対戦を続行できる。

## キャラクター画像の原寸基準表示

戦闘画像はPCで原寸を基準に最大240×240px、横画面かつ幅900px以下では75％で最大180×180px、縦画面かつ幅600px以下では約58.3％で最大140×140pxに収める。元画像の幅を読み取り、全キャラクターに同じ縮小率を使う。縦横比を維持し、表示枠が小さい場合はさらに縮小する。元画像が小さい場合は拡大しない。図鑑・編成カードの画像サイズは従来の表示を使う。

サイズは `go-ui.css` 冒頭の `--go-character-reference-size` と `--go-character-scale` で管理する。画像本体の加工は行わない。縦画面では両者の画像下端を揃え、対戦エリアの高さは表示中の背の高い画像と上下の余白に合わせて自動決定する。固定の最小152pxは設けない。既存の相手向き反転・表示位置補正・アニメーションを維持する。透明な余白を含む画像ファイルの下端が基準になる。

元へ戻す場合は `index.html` の `#go-app` にある `data-go-sprite-sizing="native-pc"` を `data-go-sprite-sizing="legacy"` に変更する。従来のサイズ指定はCSS内に保持し、この属性で追加設定だけを無効化できる。起動中の画面でも同属性を切り替えて比較できる。

Edge検証ではPC・スマホ縦・スマホ横の上限、原寸に対する縮小率、拡大しないこと、縦横比、対戦エリアからのはみ出し、旧サイズへの切替と復帰を確認する。

## ランダムバトル

タイトルと編成画面の「ランダムバトル（3対3）」から、GOの `fighterIssue()` を通過した名前・ID・正の整数スロット値を持つキャラクターを各側3体抽選する。各側は同じ候補全体から均等に非復元抽選し、チーム内の重複を除く。双方のチームに同じキャラクターを含むことは許可する。

各側で最小スロット値の個体を先発にする。同値なら抽選順の先の個体を選ぶ。抽選用乱数は引数で注入でき、通常は既存の暗号学的乱数関数を使う。候補が3体未満ならエラーを表示し、不足枠の自動生成は行わない。

生成した編成と先発を既存の設定へ渡し、`createMatch()` でプレイヤー対AIを開始する。通常の行動選択・交代・戦闘不能補充・演出・AIを使う。終了後の再戦は同じ編成と先発で初期化し、「再抽選して対戦」は両側を引き直す。通常の編成画面へ戻って編集することもできる。

自動テストでは再現可能な100シードで双方3体・重複なし・有効性・最小スロット先発を検証する。同値、候補不足、不正乱数、元データの非変更を確認する。Edgeではタイトルと編成画面からの起動、実際の先発と編成の照合、通常画面への復帰を確認する。

`viewport-fit=cover` とセーフエリアの余白を使用する。幅600px超または横画面では従来の画面配置を使い、技カードの2段階操作は全端末で共通とする。Edgeで320・375・390・430pxの縦画面、844×390pxの横画面への切替、PC幅、技詳細の開閉と誤発動防止、通常交代・相性表・戦闘・再戦を検証する。iPhone実機のSafariでの最終的なタッチ操作はユーザー環境で確認する。
