調査したMHBとGO内のMHB由来コード・データには身代わり、デコイ、能力引き継ぎに対応する処理を確認できなかった。これらはGO正式技説明と添付の暫定案を採用した。

## GOで採用した挙動

- デコイとテールパージの消費HPとデコイHPは、それぞれ最大HPにCSVの分数を掛けて切り捨てる。デコイHPが0、消費後の本体HPが0以下、既にデコイあり、または使用回数上限の場合は不成立。
- テールパージは消費・生成・交代を一体処理する。有効な控えがいなければ選択不可。使用回数は個体単位で再登場後も維持する。生成したデコイを交代先に渡し、交代先の最大HPで再計算しない。
- パワーリレーは正負両方の5能力ランクと、残存HPを含む既存デコイを引き継ぐ。控えがいなければ消費前に拒否。HP、EN、毒等はそれぞれの個体に残す。一時回避補正と次回属性攻撃の威力強化は引き継がない。
- 通常交代・攻撃後交代・戦闘不能後の補充ではデコイを解除。退場元が付けた締め付けも解除する。戦闘不能者を交代先に選べず、補充に追加行動やEN回復は発生しない。
- デコイは属性無効、消失、回避、個体・陣営軽減を判定した後、貯水の吸収・反射・反撃より先に直撃を受ける。破壊時の余剰は本体に届かない。攻撃がデコイに当たった場合の敵対象追加効果は止める。変化技とすでに付与されている継続ダメージは従来どおり本体に作用する。
- 予測・実戦で本体とデコイのダメージを別々に返す。吸収・反動は当たった側の実損HPを参照し、デコイだけへのダメージでは爪ガードとサイコカウンターを発動させない。反撃・反動で燕返しの使用者が倒れた場合は攻撃後交代を行わない。

確認が必要な暫定点は、特殊交代による締め付け突破、デコイを優先する防御順、デコイ実損を吸収・反動へ含めること、デコイ命中での燕返し、変化技がデコイを経由しないこと。今後の強制交代時はこの交代境界に別の理由を追加し、制限との優先関係を個別に決める。

## APIとCSV調整

- 通常交代は従来どおり型 switch と交代先 index。特殊技は型 move に switchIndex を併記できる。createBattle の manualSwitches を true にすると、特殊交代・補充の候補を pendingSwitch として返し、continueSwitch(battle, side, index) で再開できる。既定は順番上最初の生存控えを使う。
- 選択待ちではターンを進めず、先に確定した行動順と未実行行動を保持する。テールパージは選択確定前にEN・HPを消費しない。補充の選択待ちはターン末処理後に発生し、再開時にその処理を繰り返さない。
- onSwitch に before-switch、leave、enter、after-switch の各通知を渡せる。理由は normal、replacement、post-attack、relay、tail-purge。
- battle_effect.csv の hp_cost_ratio と decoy_hp_ratio は最大HPに対する正の分数（例 1/3）、max_uses は個体あたりの戦闘中使用上限（空欄は上限なし）。ENと発生率は skill.csv。再読込して新規戦闘を始めれば調整が反映される。
